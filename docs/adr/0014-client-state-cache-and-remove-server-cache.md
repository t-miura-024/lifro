# キャッシュをクライアントstateに一本化する

保存した内容が画面に反映されない不具合を受け、キャッシュをクライアント state（React メモリ）の 1 層へ集約することを決定した。サーバー側 Workers Cache と Service Worker の API キャッシュを廃止し、SW は静的資産とオフラインシェルのみを担う。

## Context

- 事象: 記録・メモ・種目・タイマーの保存は成功する（2xx・D1 反映済み）が、画面が更新されない。
- 原因: SW の `api-cache`（全 `/api/*` GET を Stale-While-Revalidate、最大24時間）が保存後の再取得にも古い応答を返していた。ログ詳細・メモを NetworkOnly にする除外ルールは `/api/trainings/...` を対象にしており、実際のパス `/api/logs/...` と一致しないデッドルールだった。
- サーバー側 Workers Cache（ADR 0013）は書き込み時無効化を実装済みだが、isolate をまたぐ残存窓（既定 TTL 300 秒）を best-effort でしか閉じられない。
- D1 移行（ADR 0012）で読み取りは十分高速になり、無料枠の実測消費はピーク日でも rows read 約 34 万/日（上限 500 万/日）と余裕がある。
- 目的の優先順位: (1) 保存内容の即時反映（正確性）、(2) 画面遷移時のちらつき除去（体感）、(3) 将来のピークに対する D1 クエリの安全余裕。

## Decision

- 画面データのキャッシュはクライアント state（TanStack Query、メモリのみ）の 1 層にする。
- Service Worker: `/api/**` GET を NetworkOnly にし、API キャッシュを持たない。ナビゲーション・静的資産・Google Fonts・オフラインシェルは現状維持。旧 `api-cache` は activate 時に削除する。
- サーバー: Workers Cache（CacheService / IsolateKeyLedger）と各サービスのキャッシュ呼び出しを削除する。
- HTTP: orpc クライアントは `cache: 'no-store'` で GET を素通しにする。

## 更新ポリシー

- 通常の画面遷移では再取得しない（キャッシュをそのまま表示する）。
- 保存・更新の成功時にドメイン単位で粗く更新する（`refreshLogsCache` / `refreshExercisesCache` / `refreshTimersCache`）。依存漏れによる古い表示を構造的に防ぐため、キー単位ではなくドメイン単位とする。表示中のキーはデータを保持したまま裏で再取得し（開いているモーダルの unmount を避ける）、非表示のキーは破棄して次回表示時に取得する。
  - 記録・メモの保存/削除 → logs + statistics
  - 種目（部位含む）の変更 → exercises + logs + statistics（記録表示に種目名・部位が埋め込まれるため）
  - タイマーの変更 → timers
- 明示的なリフレッシュはブラウザリロード（メモリキャッシュの全破棄）とする。専用 UI は追加しない。
- 保持はメモリのみ（リロード・再起動・別タブで破棄）。オフラインでのデータ閲覧、別タブ・別端末の同期は対象外とする。

## 退けた代替案

- SW のルールをパス別に精密化して維持: キャッシュ層が 3 つ残り、無効化契約の管理が複雑なままになる。
- サーバー Workers Cache の維持: isolate をまたぐ残存窓が残り、正確性最優先の目的と矛盾する。
- 自前のクライアントストア: 無効化・同時リクエスト制御の再実装になり、不具合の温床になる。
- sessionStorage / IndexedDB への永続化: オフラインでのデータ閲覧は要件外であり、鮮度・スキーマ管理の複雑さに見合わない。

## 影響

- cross-isolate 起因の残存窓は消滅する。一方でリクエストは常に D1 まで到達するため、D1 の rows read は増える。実測を監視し、無料枠に対して余裕がなくなった場合は別途対応する。
- この決定は ADR 0013（Upstash から Workers Cache へ置換する）を supersede する。
